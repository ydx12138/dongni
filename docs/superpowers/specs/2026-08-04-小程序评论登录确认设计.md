# 小程序评论登录确认设计

## 目标

用户在微信小程序文章详情页发表评论时，未登录状态不再立即发起微信登录。先由用户确认，确认后才执行既有微信登录流程并发布评论。

## 范围

- 仅修改 `blogweixin` 的文章详情评论交互。
- 不修改后端接口、微信登录服务、数据库结构或 PC 前端。
- 保留现有微信用户自动创建、token 保存和评论接口逻辑。

## 交互流程

1. 用户在文章详情页输入评论并点击发布。
2. 已保存 `access_token` 时，直接调用现有评论接口。
3. 未保存 `access_token` 时，显示微信原生确认弹窗，提示“登录后才能发表评论，是否继续？”。
4. 用户选择取消：关闭弹窗，不调用 `wx.login`，不提交评论，输入框内容保持不变。
5. 用户选择登录：调用现有 `ensureLogin()`，该函数继续通过 `wx.login` 和 `POST /api/wechat/login` 获取并保存 token。
6. 登录成功后，自动提交本次原评论内容；成功后刷新评论列表并清空输入框。

## 异常处理

- 微信登录失败或评论接口失败时，显示错误提示。
- 任意失败都不清空评论输入内容，用户可以再次尝试。
- 弹窗取消时恢复可提交状态，避免按钮保持加载状态。

## 验收标准

- 未登录发布评论时，先出现确认弹窗，且取消不会触发登录请求。
- 确认登录后，成功登录会自动完成原评论发布。
- 已登录发布评论不显示确认弹窗。
- 登录或发布失败后，评论文本仍保留。

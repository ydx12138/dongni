# 微信强制手机号登录实施计划

> **供自动化执行者使用：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐项执行。本计划使用复选框跟踪进度。

**目标：** 让具备微信手机号能力的小程序在手机号授权并保存成功后才获得正式 JWT。

**架构：** `POST /api/wechat/login` 仅识别 `openid`：已有手机号的用户直接获得 token，没有手机号的用户获得 Redis 中的一次性 `phone_ticket`。新的 `POST /api/wechat/phone` 使用 ticket 和微信手机号 code 换取、唯一校验并保存手机号，最后复用既有 `issueUserTokens` 签发 token。小程序将授权页面与现有 `ensureLogin` 分开，避免在未授权时写入 token。

**技术栈：** Go 1.25、Gin、GORM、Redis、微信小程序 `wx.login`/`open-type="getPhoneNumber"`、Node.js 内置测试。

## 计划自检

- 规格覆盖：强制授权、手机号换取、Redis 一次性 ticket、唯一性、token 延后签发、异常与小程序状态均有对应任务。
- 未包含昵称获取、PC 前端、管理端、旧手机号更新接口或其他无关改动。
- 名称一致：所有服务端和小程序请求均使用 `phone_ticket` 与 `code`；token 仅由 `issueUserTokens` 产生。

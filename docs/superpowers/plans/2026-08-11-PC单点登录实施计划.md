# PC 单点登录实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 PC 邮箱登录增加基于 Redis `session_id` 的单点登录，并让 PC 前端在检测到异地登录后自动清除登录状态。

**Architecture:** PC 邮箱登录单独生成会话 ID，写入 JWT 和 Redis；普通用户鉴权通过已注入的 `RedisMiddleRepository` 对比当前会话。保留旧的通用 Token 生成入口供管理员和微信流程使用，避免改变微信小程序行为。PC 请求层统一识别业务码 `1008` 并通知认证状态仓库退出。

**Tech Stack:** Go、Gin、JWT、Redis、Go testing、Vue 3、Vite。

为兼容现有 `service.New(repo, redis, exchanger)` 调用，新增的会话 Repository 依赖使用可选参数；`app.NewContainer` 将 `authMiddleRepo` 同时传给 Service。微信仍调用原有无会话签发流程。

在 `pkg/code/code.go` 增加：


Service 的会话校验读取当前 Redis 会话；Redis 错误返回错误，空值或不一致返回 `ErrSessionInvalid`。

- [ ] **Step 3: 在 `auth.go` 中使用 `redisMiddleRepo` 校验 PC 会话**

### Task 4: PC 前端自动退出与登录 Token 字段修正

**Files:**
- Modify: `vue6122/src/api/client.js`
- Modify: `vue6122/src/stores/auth.js`

- [ ] **Step 1: 确认前端测试环境并记录验证方式**

检查 `vue6122/package.json`。项目没有前端测试脚本，因此本任务使用源码级检查和 Vite 构建验证：确认响应 `{code: 1008, message: "账号已在其他地方登录"}` 会删除 `blog-token`、`blog-user` 并派发 `blog:session-replaced` 事件，普通错误码不会删除登录态。

- [ ] **Step 2: 实现请求层处理**

在 `client.js` 中定义 `SESSION_REPLACED_CODE = 1008`。解析响应后先处理该业务码：清理 PC 用户 Token 和用户缓存，调用 `window.dispatchEvent(new CustomEvent('blog:session-replaced'))`，再抛出带 `code` 属性的 Error。管理员 Token 不在清理范围内。

- [ ] **Step 3: 实现 auth store 响应式退出**

在 `auth.js` 注册一次事件监听，收到 `blog:session-replaced` 后将 `state.user` 设为 `null`；同时提供统一的清理逻辑，避免只删 localStorage 而页面仍显示登录状态。

- [ ] **Step 4: 修正 PC 登录返回字段**

`login()` 使用后端返回的 `data.access_token` 保存到 `blog-token`，同时保留用户资料写入逻辑。刷新接口的调用方继续读取后端的 `access_token`。

# 微信强制手机号登录设计

## 目标

为具备微信手机号能力的小程序提供可迁移的登录模块：用户必须授权获取其微信绑定手机号后，才获得本系统的正式登录态。

## 范围

- 扩展 Go 后端的微信客户端、用户模型、repository、service、handler 和路由。
- 扩展微信原生小程序的登录调用与手机号授权界面。
- 不读取微信昵称，不修改邮箱登录、密码重置、评论、PC 前端或管理端。
- 当前个人主体小程序可能没有手机号能力；代码面向已获得该能力的目标小程序，当前项目只完成静态与模拟测试。

## 账号与数据

- `users.wechat_open_id` 继续作为微信身份的唯一标识。
- `users.phone` 改为可空唯一字段，避免同一手机号绑定多个账号。
- 用户首次微信登录时先创建内部邮箱、随机密码、默认昵称和 `openid`，但未完成手机号前不签发 JWT。
- 已有 `openid` 的用户同样必须有手机号才可获得 JWT。
- 手机号已经属于其他用户时拒绝绑定，不覆盖既有数据。

## 接口与流程

### 1. 发起微信登录

小程序由用户点击按钮触发 `wx.login`，调用 `POST /api/wechat/login`：

```json
{ "code": "wx.login 返回的临时 code" }
```

后端调用 `jscode2session` 得到 `openid`，查询或创建用户。

- 用户已有手机号：直接返回现有 JWT、refresh token 和基础用户信息。
- 用户没有手机号：生成不可预测的短期一次性 `phone_ticket`，存入 Redis 并关联用户 ID，返回：

```json
{ "phone_required": true, "phone_ticket": "一次性短期凭证" }
```

该响应不返回 JWT。`phone_ticket` 只用于下一步绑定，使用后立即失效。

### 2. 用户授权手机号

小程序展示不可跳过的手机号授权页，使用：

```xml
<button open-type="getPhoneNumber" bindgetphonenumber="onGetPhoneNumber">授权并登录</button>
```

用户同意后，事件中获得一次性手机号 `code`。小程序调用 `POST /api/wechat/phone`：

```json
{ "phone_ticket": "步骤 1 返回的凭证", "code": "getPhoneNumber 返回的临时 code" }
```

用户拒绝、未携带 `code` 或后端验证失败时，停留在授权页，不保存 token，也不进入业务页面。

### 3. 后端换取和保存手机号

后端微信客户端负责：

1. 使用 AppID 与 AppSecret 获取微信接口 `access_token`，仅保存在服务端内存缓存，按微信响应的有效期提前刷新。
2. 调用微信 `getuserphonenumber`，以手机号授权码换取 `phone_info.purePhoneNumber`。
3. 验证手机号非空，检查唯一性，更新对应用户的手机号。
4. 删除 Redis 中的 `phone_ticket`，按现有机制签发 JWT 和 refresh token。

微信接口密钥、openid、手机号授权码、手机号和 `phone_ticket` 均不得写入日志或返回给非当前用户。

## 错误处理

- 微信登录配置缺失、登录 code 无效、微信接口响应错误：返回登录失败，不创建可用会话。
- `phone_ticket` 缺失、过期、已使用或与当前流程不匹配：拒绝手机号绑定。
- 手机号授权码缺失、失效或微信返回空手机号：拒绝绑定，用户可重新点击授权。
- 手机号重复：返回明确的冲突错误，不更改任何用户记录。
- 数据库更新失败：不签发 token；仅在手机号成功持久化后删除 `phone_ticket`。

## 测试与验收

- 微信客户端测试覆盖 access token 获取、手机号换取成功、微信错误响应和空手机号。
- service 测试覆盖未绑定用户只得到 `phone_ticket`、绑定成功后才得到 JWT、过期凭证和重复手机号被拒绝。
- handler 测试覆盖两个接口的缺失字段校验。
- 小程序静态测试覆盖：手机号未授权不保存 token；获取到手机号 code 后发送 `phone_ticket`；后端返回 token 后才落盘。
- 在有手机号能力的目标小程序中手测：首次登录授权后成功进入业务页面；拒绝授权无法进入；后续登录直接获得 token。
